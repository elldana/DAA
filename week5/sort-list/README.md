# Sort List

## 1. Problem
Дан указатель на голову односвязного списка. Необходимо отсортировать этот список по возрастанию значений и вернуть новую голову. Требование задачи: алгоритм должен работать за время $O(n \log n)$.

## 2. Approach
Для связных списков оптимальнее всего подходит Merge Sort:
1. **Базовый случай**: если в списке 0 или 1 узел, он уже отсортирован.
2. **Поиск середины и разделение**: используем технику двух указателей (медленный `slow` и быстрый `fast`). `fast` двигается на 2 шага, `slow` — на 1 шаг. Дополнительный указатель `prev` идет прямо перед `slow`. Когда `fast` доходит до конца, `slow` оказывается в начале второй половины. Мы делаем `prev.next = null`, тем самым физически разрезая список на две независимые части.
3. **Рекурсивный спуск**: вызываем `sortList` для левой головы (`head`) и для правой головы (`slow`).
4. **Слияние**: соединяем два упорядоченных списка методом `merge` (используя `dummy`-узел и сравнение значений, аналогично задаче *Merge Two Sorted Lists*).

### Tracing Example
Возьмем список: `4 -> 2 -> 1 -> 3`

- **Шаг 1: Разделение списка**:
  - `slow` доходит до узла `1`, `prev` на узле `2`.
  - Разрываем: `prev.next = null`.
  - Получили два списка: `4 -> 2` и `1 -> 3`.
- **Шаг 2: Рекурсивный спуск дальше**:
  - `4 -> 2` делится на `[4]` и `[2]`.
  - `1 -> 3` делится на `[1]` и `[3]`.
- **Шаг 3: Слияние малых списков**:
  - Сливаем `[4]` и `[2]`: получаем `2 -> 4`.
  - Сливаем `[1]` и `[3]`: получаем `1 -> 3`.
- **Шаг 4: Финальное слияние**:
  - Сливаем `2 -> 4` и `1 -> 3`:
    - Сравниваем 2 и 1 -> берем 1.
    - Сравниваем 2 и 3 -> берем 2.
    - Сравниваем 4 и 3 -> берем 3.
    - Доцепляем хвост 4.
  - Результат: `1 -> 2 -> 3 -> 4`.

### Challenges & Mistakes
- Самая опасная ошибка возникла на этапе разрыва списка. Если просто найти середину и не разорвать связь `prev.next = null`, то левая половина продолжит ссылаться на правую. В итоге рекурсия попадает в бесконечный цикл деления одного и того же списка и падает с `StackOverflowError`.
- Была мысль просто выгрузить все значения списка в `ArrayList`, отсортировать через `Collections.sort()` и перезаписать значения в узлы. Это проходит тесты, но по сути обходит работу со структурой связного списка и требует $O(n)$ лишней памяти под массив. Поэтому честное решение через перелинковку указателей в `merge` гораздо чище с точки зрения алгоритмов.

## 3. Time Complexity
**Time Complexity: O(n log n)**

**Why:**  
Список делится пополам за $O(n)$ на каждом уровне рекурсии с помощью указателей `slow` и `fast`. Всего уровней деления $\log_2 n$. На каждом уровне операция слияния двух списков обходит все элементы за $O(n)$. Суммарно получаем $O(n \log n)$.

## 4. Space Complexity
**Space Complexity: O(log n)**

**Why:**  
Мы не создаем новые узлы списка — операция слияния лишь перенаправляет ссылки `next` существующих объектов. Однако рекурсивные вызовы создают фреймы в стеке вызовов. Глубина дерева рекурсии равна $\log_2 n$, поэтому затраты памяти на стек составляют $O(\log n)$.

## 5. Reflection / Improvement
- **Можно ли сделать $O(1)$ по памяти?**  
  Да, если переписать Merge Sort в итеративном виде (Bottom-Up подход). Вместо рекурсивного разделения списка сверху вниз, мы итеративно соединяем подсписки длины 1, затем длины 2, 4, 8 и так далее, пока размер шага не превысит длину списка. Это исключит стек вызовов и даст строго $O(1)$ дополнительной памяти.
