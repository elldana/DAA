# Sort an Array

## 1. Problem
Нам дан массив целых чисел `nums`. Нужно отсортировать его элементы по возрастанию без использования встроенных библиотечных методов сортировки вроде `Arrays.sort()`

## 2. Approach
Для решения я выбрала классический алгоритм сортировки слиянием (Merge Sort)

1. Базовый случай рекурсии: если подотрезок массива состоит из одного элемента или пуст (`left >= right`), сортировать нечего, просто выходим
2. Делим текущий отрезок пополам: находим середину `mid = left + (right - left) / 2`
3. Рекурсивно вызываем `mergeSort` для левой половины (`left` .. `mid`) и правой половины (`mid + 1` .. `right`).
4. Вспомогательный метод `merge` объединяет два уже отсортированных подотрезка во временный массив `temp`, сравнивая элементы с помощью двух указателей `i` и `j`.
5. После слияния переносим упорядоченные числа обратно в оригинальный массив на свои позиции.

### Tracing Example
Возьмем массив `[5, 2, 3, 1]`:
- **Разделение**:
  - `[5, 2, 3, 1]` делится на `[5, 2]` и `[3, 1]`.
  - `[5, 2]` делится на `[5]` и `[2]`.
  - `[3, 1]` делится на `[3]` и `[1]`.
- **Слияние 1 уровня**:
  - Сливаем `[5]` и `[2]`: сравниваем $5 > 2$, получаем `[2, 5]`.
  - Сливаем `[3]` и `[1]`: сравниваем $3 > 1$, получаем `[1, 3]`.
- **Слияние 2 уровня**:
  - Сливаем `[2, 5]` и `[1, 3]`:
    - Шаг 1: сравниваем 2 и 1 -> пишем 1 в `temp`.
    - Шаг 2: сравниваем 2 и 3 -> пишем 2 в `temp`.
    - Шаг 3: сравниваем 5 и 3 -> пишем 3 в `temp`.
    - Шаг 4: правая часть закончилась, дописываем 5 -> `temp = [1, 2, 3, 5]`.
- Копируем `temp` в `arr`. Массив отсортирован.

### Challenges & Mistakes
- В первой попытке я попробовала обычный QuickSort с выбором опорного элемента как первого или последнего элемента подмассива (`arr[left]` или `arr[right]`). На LeetCode есть тесткейсы с уже отсортированными массивами и массивами из одинаковых чисел — в этих случаях такой QuickSort деградировал до сложности $O(n^2)$ и падал по `Time Limit Exceeded`.
- Также при вычислении середины сначала написала `mid = (left + right) / 2`. Для больших размеров массива это может привести к переполнению целого числа (Integer Overflow), поэтому безопаснее использовать формулу `left + (right - left) / 2`.
- Сортировка слиянием гарантирует строгое $O(n \log n)$ в любых крайних случаях, поэтому перешла на нее.

## 3. Time Complexity
**Time Complexity: O(n log n)** в лучшем, среднем и худшем случаях.

**Why:**  
На каждом шаге рекурсии массив делится ровно пополам, что дает дерево вызовов глубиной $\log_2 n$. На каждом уровне дерева суммарно просматриваются и сливаются все $n$ элементов массива за $O(n)$

## 4. Space Complexity
**Space Complexity: O(n)**

**Why:**  
Для операции слияния нам требуется дополнительный массив `temp`, вмещающий объединяемый подотрезок. В худшем случае на верхнем уровне слияния размер временного массива равен $n$. Стек вызовов рекурсии занимает $O(\log n)$, поэтому доминирует память массива $O(n)$.

## 5. Reflection / Improvement
- **Альтернативы:**  
  HeapSort (пирамидальная сортировка) также обеспечивает $O(n \log n)$ по времени, но при этом требует $O(1)$ дополнительной памяти, так как сортирует элементы прямо на месте в виде кучи.
