# Palindrome Linked List

## 1. Problem
Дан односвязный список. Нужно определить, является ли он палиндромом (читается ли последовательность одинаково слева направо и справа налево). Если да — вернуть `true`, если нет — `false`.

## 2. Approach
Односвязный список неудобен тем, что по нему нельзя ходить назад. Поэтому самое понятное решение «в лоб» — перенести все значения в обычный массив, где есть доступ по индексам:

1. Создаем список `ArrayList<Integer> values`.
2. Проходим по связному списку и складываем все значения `current.val` в массив.
3. Ставим два указателя: `left = 0` на начало массива и `right = values.size() - 1` на конец.
4. В цикле сдвигаем указатели навстречу друг другу:
   - Если `values.get(left)` не равно `values.get(right)`, сразу возвращаем `false`.
   - Иначе делаем `left++` и `right--`.
5. Если указатели встретились и несовпадений не нашлось, возвращаем `true`.

### Tracing Example
Пример: `head = [1, 2, 2, 1]`

- **Шаг 1 (копирование)**:  
  `values = [1, 2, 2, 1]`.
- **Шаг 2 (два указателя)**:  
  - `left = 0` (`val = 1`), `right = 3` (`val = 1`). Они равны. `left = 1`, `right = 2`.
  - `left = 1` (`val = 2`), `right = 2` (`val = 2`). Они равны. `left = 2`, `right = 1`.
- Цикл завершился (`left >= right`).
- Возвращаем `true`.

### Challenges & Mistakes
- **Коварная ошибка в Java с `!=`:** Когда мы достаем элементы из `List<Integer>`, мы получаем объекты-обертки `Integer`. Если написать `values.get(left) != values.get(right)`, то при числах больше 127 Java не использует Integer Cache и начинает сравнивать ссылки на объекты, а не сами числа! Из-за этого одинаковые числа признавались разными, и тест падал. Обязательно нужно использовать `.equals()`.
- Изначально я думала развернуть весь связный список и сравнить с оригиналом, но разворот ломает исходный список прямо в памяти, и сравнивать становится не с чем без полного глубокого клонирования. Поэтому решение через `ArrayList` оказалось проще всего.

## 3. Time Complexity
**Time Complexity: O(n)**, где $n$ — количество узлов в списке.  
**Why:** Мы делаем один проход по связному списку для копирования значений в массив ($O(n)$), и затем один проход двумя указателями по массиву до середины ($O(n/2) \approx O(n)$). Суммарно получается $O(n)$.

## 4. Space Complexity
**Space Complexity: O(n)**  
**Why:** Нам требуется дополнительный массив `ArrayList`, который хранит $n$ элементов связного списка.
