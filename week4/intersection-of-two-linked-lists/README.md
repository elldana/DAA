# Intersection of Two Linked Lists

## 1. Problem
Даны два односвязных списка `headA` и `headB`. Нужно найти узел, в котором они соединяются (начинают разделять общие узлы). Если списки вообще не пересекаются, вернуть `null`. Важно: пересечение определяется не по равенству значений `val`, а по совпадению ссылок на один и тот же объект в памяти.

## 2. Approach
Я выбрала прямолинейный и понятный подход через хэш-таблицу (`HashSet`):
1. Создаем `HashSet<ListNode> visitedNodes`.
2. Пробегаем первый список `A` от начала до конца и складываем в сет сами ссылки на узлы.
3. Затем начинаем идти по списку `B`. На каждом шаге проверяем: есть ли текущий узел `currB` уже в нашем сете?
4. Первый же узел, который мы найдем в сете — это и есть начало пересечения, сразу возвращаем его.
5. Если дошли до конца списка `B` и ничего не нашли, значит списки параллельны — возвращаем `null`.

### Tracing Example
Список A: `4 -> 1 -> [8 -> 4 -> 5]`  
Список B: `5 -> 6 -> 1 -> [8 -> 4 -> 5]`  
(узел со значением 8 — общий объект в памяти).

- **Обход A**:
  - Добавили в сет ссылки: `Node(4)`, `Node(1)`, `Node(8)`, `Node(4_last)`, `Node(5)`.
- **Обход B**:
  - `currB = Node(5_b)`: нет в сете.
  - `currB = Node(6)`: нет в сете.
  - `currB = Node(1_b)`: нет в сете (хотя значение 1, объект другой).
  - `currB = Node(8)`: **есть в сете!** Ссылка совпала.
- Возвращаем `Node(8)`.

### Challenges & Mistakes
- Сначала была мысль просто в лоб сравнивать значения `currA.val == currB.val`. Но это фатальная ошибка: узлы могут иметь одинаковые числа (например, 1 и 1), но не пересекаться физически. Пересечение — это именно общая ссылка `next`.
- Еще пыталась сопоставить списки просто по индексам, но списки имеют разную длину до точки пересечения, так что идти синхронно с начала списков в лоб нельзя. Поэтому решение с `HashSet` показалось самым надежным и простым для понимания.

## 3. Time Complexity
**Time Complexity: O(n + m)**, где $n$ — длина списка A, $m$ — длина списка B.  
**Why:** Мы сначала делаем $n$ итераций по первому списку, чтобы заполнить хэш-сет. Затем в худшем случае делаем $m$ итераций по списку B. Поиск и добавление в `HashSet` работают в среднем за $O(1)$. Итого $O(n + m)$.

## 4. Space Complexity
**Space Complexity: O(n)**  
**Why:** Нам приходится хранить все $n$ узлов списка A в `HashSet`.
