# Linked List Cycle

## 1. Problem
Нам дан односвязный список. Нужно определить, зациклен ли он. Список считается циклическим, если какой-то узел через цепочку указателей `next` снова ссылается на ранее пройденный узел, из-за чего обход списка никогда не завершится. Если цикл есть — возвращаем `true`, если нет — `false`

## 2. Approach
Я использовала алгоритм Флойда для поиска цикла (черепаха и заяц / Two Pointers):

1. Если список пустой (`head == null`) или состоит из одного узла без цикла (`head.next == null`), сразу возвращаем `false`.
2. Заводим два указателя: `slow` и `fast`, оба изначально смотрят на `head`.
3. В цикле двигаем:
   - `slow` на 1 шаг вперед: `slow = slow.next`
   - `fast` на 2 шага вперед: `fast = fast.next.next`
4. Логика: если цикла нет, `fast` быстро дойдет до конца списка (`null`), и цикл `while` завершится. Если цикл есть, `fast` зайдет в него раньше и начнет бегать по кругу, пока `slow` тоже не войдет в цикл. Поскольку расстояние между ними на каждом шаге сокращается ровно на 1 узел, `fast` гарантированно догонит `slow`.
5. Если в какой-то момент ссылки совпали (`slow == fast`), значит, цикл найден — возвращаем `true`.

### Tracing Example
Возьмем классический пример с циклом: `head = [3, 2, 0, -4]`, где узел `-4` ссылается обратно на узел `2` (индекс 1).

- Старт: `slow` на `3`, `fast` на `3`.
-Итерация 1:  
  `slow` идет на 1 шаг -> узел `2`.  
  `fast` идет на 2 шага -> узел `0`.  
  `slow != fast`.
-Итерация 2:  
  `slow` идет на 1 шаг -> узел `0`.  
  `fast` идет на 2 шага -> от `0` к `-4`, от `-4` по циклу к `2`. Теперь `fast` на `2`.  
  `slow != fast`.
- Итерация 3:  
  `slow` идет на 1 шаг -> узел `-4`.  
  `fast` идет на 2 шага -> от `2` к `0`, от `0` к `-4`. Теперь `fast` на `-4`.  
  Условие `slow == fast` выполнено (оба указывают на узел `-4`).
- Выход: возвращаем `true`.

## 3. Time Complexity
**Time Complexity: O(n)**, где $n$ — количество узлов в списке.

Why:
- Если цикла нет, `fast` дойдет до конца списка за $n / 2$ шагов, то есть $O(n)$.

## 4. Space Complexity
Space Complexity: O(1)

Why:
Мы используем всего две ссылочные переменные (`slow` и `fast`). Мы не выделяем память под структуры данных и не храним адреса узлов, поэтому расход дополнительной памяти фиксированный.

## 5. Reflection / Improvement
- **Альтернативное решение (Naive / HashSet):**  
  Можно было бы просто складывать каждый посещенный узел в `HashSet<ListNode>`. Перед добавлением проверять: если узел уже есть в сете — цикл найден.  
  - Минус: это требует $O(n)$ дополнительной памяти под хэш-таблицу.
- **Сравнение:**  
  Алгоритм двух указателей (черепаха и заяц) выигрывает по памяти ($O(1)$ против $O(n)$) при той же временной сложности $O(n)$, поэтому текущее решение уже является оптимальным.
