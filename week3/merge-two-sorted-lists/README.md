# Merge Two Sorted Lists

## 1. Problem
У нас есть два отсортированных односвязных списка`list1` и `list2`. Нужно объединить их в один общий отсортированный список, просто переставляя указатели существующих узлов (не создавая новые узлы со значениями заново). На выходе нужно вернуть голову нового списка

## 2. Approach
Я использовала итеративный подход с двумя указателями и одним вспомогательным узлом (`dummy`):

1. Создаем фиктивный узел `dummy = new ListNode(0)`. Он нужен просто для удобства, чтобы не проверять отдельно, какой узел станет первой головой нового списка
2. Ставим указатель `current` на `dummy`
3. В цикле `while` сравниваем значения `list1.val` и `list2.val`:
   - Если `list1.val <= list2.val`, привязываем `current.next` к `list1` и двигаем `list1 = list1.next`.
   - Иначе привязываем `current.next` к `list2` и сдвигаем `list2 = list2.next`
   - В любом случае сдвигаем `current = current.next`
4. Когда один из списков закончился, цикл прерывается. Оставшуюся часть второго списка (она ведь уже отсортирована) мы просто прицепляем в конец: `current.next = (list1 != null) ? list1 : list2`
5. Возвращаем `dummy.next`

### Tracing Example
Возьмем пример: `list1 = [1, 2, 4]`, `list2 = [1, 3, 4]`

- Старт: `dummy -> 0`, `current` на `dummy`. `list1` указывает на `1`, `list2` указывает на `1`.
-Шаг 1: Сравниваем 1 и 1. Они равны, берем из `list1`.  
  `current.next = 1 (из list1)`. Сдвигаем `list1` на 2. Сдвигаем `current`.  
  Результат: `dummy -> 1`.
- Шаг 2: Сравниваем 2 (list1) и 1 (list2). 1 меньше, берем из `list2`.  
  `current.next = 1 (из list2)`. Сдвигаем `list2` на 3. Сдвигаем `current`.  
  Результат: `dummy -> 1 -> 1`.
- Шаг 3: Сравниваем 2 (list1) и 3 (list2). 2 меньше.  
  `current.next = 2`. Сдвигаем `list1` на 4.  
  Результат: `dummy -> 1 -> 1 -> 2`.
- Шаг 4: Сравниваем 4 (list1) и 3 (list2). 3 меньше.  
  `current.next = 3`. Сдвигаем `list2` на 4.  
  Результат: `dummy -> 1 -> 1 -> 2 -> 3`.
- Шаг 5: Сравниваем 4 (list1) и 4 (list2). Берем из `list1`.  
  `current.next = 4`. `list1` становится `null`.  
  Результат: `dummy -> 1 -> 1 -> 2 -> 3 -> 4`.
- После цикла: `list1 == null`, но в `list2` остался узел `4`. Просто прицепляем его к концу: `current.next = list2`.  
- Финал: `1 -> 1 -> 2 -> 3 -> 4 -> 4`. Возвращаем `dummy.next`.

## 3. Time Complexity
**Time Complexity: O(n + m)**, где $n$ — длина первого списка, а $m$ — длина второго списка.

**Why:**  
На каждой итерации цикла `while` мы берем ровно один элемент либо из `list1`, либо из `list2` и продвигаемся на один шаг вперед. В худшем случае мы пройдем по всем узлам обоих списков, пока они оба почти не закончатся. То есть общее количество операций прямо пропорционально сумме длин списков ($n + m$).

## 4. Space Complexity
**Space Complexity: O(1)**

**Why:**  
Мы не создаем новые узлы для элементов списков и не копируем массивы. Мы выделили память только под один вспомогательный узел `dummy` и указатель `current`. Дальше мы просто переставляем ссылки `next` у уже существующих узлов в куче

## 5. Reflection / Improvement
- **Есть ли более эффективный алгоритм?**  
  По времени ($O(n + m)$) и по памяти ($O(1)$) этот алгоритм уже оптимальный, быстрее пройти оба списка физически нельзя, так как нужно посмотреть на каждый узел хотя бы один раз.
- **Альтернативы:**  
  Эту задачу можно решить рекурсивно, но рекурсия займет $O(n + m)$ дополнительной памяти в стеке вызовов (call stack), поэтому итеративный вариант практичнее и безопаснее от `StackOverflowError`.
